In this lesson, you'll explore system logs from a host machine using both curated dashboards and Discover. You'll learn to navigate pre-built visualizations for quick insights and construct KQL queries for targeted investigations—two complementary approaches that form the foundation of log-based troubleshooting in Elastic Observability.


Key terms
Term	Definition
Data view	A pattern that defines which indices Discover and dashboards can query (e.g., logs-*)
KQL (Kibana Query Language)	A simple query syntax for filtering data in Kibana using field:value pairs and boolean operators
Syslog	A standard protocol and format for system logging on Unix/Linux systems
event.dataset	A field that identifies the source integration or module that collected the log entry

Discover
Navigate to Discover and select the logs-* data view.eoe-2-2-c2-Discover-Logs-DV.png

🔍 Why this matters
The logs-* data view matches all indices that follow Elastic's naming convention for log data. This includes logs from the System integration, Custom Logs, Nginx, and any other log-producing integrations you've configured.

Enter the query log.file.path: "/var/log/auth.log" and message: "session opened for user" to display log events from /var/log/auth.log where the message contains the terms "session opened for user".eoe-2-2-c2-discover-session-opened.png

🔍 Why this matters
The log.file.path field lets you filter logs by their source file, while searching the message field finds specific content. Combining these filters is a common pattern for investigating specific events from known log sources.

Enter the query log.file.path : ("/var/log/syslog" OR "/var/log/auth.log") to only display log events from either /var/log/syslog or /var/log/auth.log.Screenshot 2026-01-23 at 8.55.45 AM.png
